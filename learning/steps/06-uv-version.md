## 新名词

- **项目版本要求**：项目配置文件明确规定工具必须满足的版本范围；`>=0.9.0` 表示大于或等于 0.9.0。
- **执行文件位置**：输入命令后，操作系统实际运行的文件路径。
- **命令搜索路径**：环境变量 `PATH` 保存的一组目录；终端按顺序在这些目录中寻找可执行命令。
- **符号链接**：指向另一个文件的入口。本环境的 `/root/.local/bin/uv` 指向 `pipx` 隔离环境中的实际文件。
- **pipx**：把 Python 命令行应用分别安装在隔离虚拟环境中的工具，使这些应用可以从命令搜索路径直接执行。
- **虚拟环境**：为一个 Python 应用隔离软件包的目录，防止它与系统 Python 或其他应用的包相互冲突。
- **软件包索引**：安装器查询和下载软件包的服务器目录；本次使用的官方服务是 Python Package Index。
- **网络代理**：在当前环境与外部服务器之间转发请求的服务；它可以依据环境策略允许或拒绝连接。
- **缓存**：以前下载后保存在本机、可在没有网络时重复使用的文件。

`python3 -m pip show uv` 找不到系统 Python 中的 `uv` 包，而符号链接、pipx 环境路径及 `pipx_metadata.json` 一致证明当前工具由 pipx 管理。命令搜索路径中只找到这一套 `uv`。

原安装约束 `uv==0.7.*` 把工具限制在 0.7 系列，所以单纯执行 `pipx upgrade uv` 不能可靠越过该约束。为保持原安装方式并满足项目最低版本，选用下面的安装规格：

```bash
pipx install --force 'uv>=0.9.0'
```

其中 `--force` 允许 pipx 修改现有同名虚拟环境和命令入口；单引号防止命令解释器把 `>` 当成输出重定向符号。当前 pipx 自带帮助确认，`install` 会创建隔离虚拟环境并把应用入口放入 `PATH`，而 `--force` 可修改已存在的环境和入口。

## 知识点总结

- 工具能够执行不等于版本符合项目要求，应同时核对配置声明和实际版本。
- 升级前应先识别安装来源；pipx 管理的工具继续用 pipx 处理，可以避免并存多套入口。
- `uv==0.7.*` 会限制升级范围；把工具安装规格改为 `uv>=0.9.0` 不等于降低或篡改项目要求。
- “没有匹配发行包”也可能由网络在读取版本列表前失败造成，应结合连接重试和状态码定位。
- 安装失败后必须复核旧版本是否保留，不能假定环境保持不变或假定升级成功。

## 面试题与参考答案

**问题一：为什么 `uv --version` 成功，仍不能继续安装项目依赖？**

因为命令成功只证明 uv 可以执行。项目要求最低版本为 0.9.0，而实际是 0.7.22；旧工具可能不能正确解释当前配置，所以应先解决工具版本差异。

**问题二：为什么升级前要检查执行路径和安装方式？**

同一台机器可能存在多套同名命令。如果用另一种方式安装新版，命令搜索路径仍可能优先运行旧版。确认当前 uv 由 pipx 管理后继续使用 pipx，可以更新实际入口并减少冲突。

**问题三：安装器报告没有匹配版本时，应怎样排查？**

先区分版本约束、操作系统或处理器兼容性、软件包索引配置和网络连接。本次索引查询在得到版本列表前连续收到代理的 403 响应，官方发布页也被同一代理拒绝，所以根因是外部连接受限，而不是可以据此断言 uv 没有新版本。

**问题四：安装失败后为什么还要再次运行旧版？**

带 `--force` 的操作可能修改已有环境。必须重新检查入口、真实路径和版本，才能确认旧环境是否被保留，并决定可以安全重试还是需要恢复。
