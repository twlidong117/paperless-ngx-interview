## 本步出现的新名词及解释

- **shell（命令解释器）**：接收并执行终端命令的程序；它会按照 `PATH` 中的目录顺序寻找 `uv`。
- **命令入口**：输入命令后，shell 首先找到的可执行文件或链接。本次入口是 `/root/.local/bin/uv`。
- **符号链接**：指向另一个文件的入口；解析链接可以确认最终执行的文件，而不只记录表面路径。
- **语义化版本比较**：按版本号各数字部分比较，而不是按普通字符串比较。例如 `0.12.12` 高于 `0.9.0`。
- **退出状态**：命令结束时返回的数字；本次检查中 `0` 表示相应命令成功。

## 具体操作

执行者：Codex。执行位置：仓库根目录 `/workspace/paperless-ngx-interview`。

1. `type -a uv`：列出 shell 能找到的全部 `uv` 入口。预期至少有一个结果；没有输出或返回非零状态表示未找到命令。
2. `command -v uv`：输出本次优先执行的入口。预期得到一个绝对路径。
3. `readlink -f "$(command -v uv)"`：沿符号链接解析到最终文件。`-f` 表示解析路径中的全部链接组成部分。
4. `uv --version`：让实际命令报告版本。预期输出可解析的三段数字版本号。
5. 将解析出的版本与 `0.9.0` 一同交给 `sort -V`；`-V` 表示按版本号排序。如果较小者是 `0.9.0`，实际版本便满足最低要求。

## 面试题与参考答案

**问题一：为什么既要运行 `command -v uv`，又要运行 `uv --version`？**

前者确认 shell 选择了哪个命令入口，后者确认该入口实际运行后报告什么版本。只做其中一个，无法同时证明执行对象和版本要求都正确。

**问题二：为什么还要使用 `readlink -f`？**

命令入口可能是符号链接。解析后可以知道最终执行文件位于 pipx 的隔离环境，避免把入口路径误认为真实文件位置，也有助于排查多套安装之间的冲突。

**问题三：怎样判断 `0.12.12` 是否满足 `>=0.9.0`？**

按版本数字从左到右比较：主版本同为 0，次版本 12 大于 9，因此 `0.12.12` 高于 `0.9.0`。本次还用 `sort -V` 做了程序化比较，结果为通过。

**问题四：如果 `uv --version` 成功，能否说明 Paperless-ngx 已经可以运行？**

不能。这只证明 uv 这一项前置条件符合要求；项目的 Python 依赖、外部工具、配置、数据库迁移和应用启动均需各自验证。本次明确没有安装依赖或启动应用。
