## 新名词

- 工作目录：任务当前读取、修改文件的地方。
- 分支：一条代码演进路线的名称；不同名称可以指向同一次提交。
- 提交：保存一组变更的历史记录；提交标识用于准确定位它。
- 父提交：当前提交直接建立在其上的历史记录。
- 远程仓库配置：本地记录的服务器仓库名称和地址，属于连接配置。
- 工作目录干净：Git 状态检查在当前选项和配置下没有报告待提交变更，不是功能正确的证明。
- 交叉核对：使用另一来源的记录检查同一事实是否一致。

## 知识点总结

- 目录名称、文档中的仓库地址、远程配置、操作权限分别提供不同证据。
- 比较提交标识比只比较分支名更能定位代码历史起点；还需检查未提交变更。
- 工作目录干净不等于程序功能正确。
- 文档记录应该区分默认分支、实际任务分支和检查时间。
- 任务环境报告与当前聊天的 GitHub 验证分开归因，不互相替代。

## 面试题与参考答案

**一：两个分支名称不同，代码一定不同吗？**

不一定。两个分支可以指向同一次提交。应核对提交和未提交变化，不能只看名字。

**二：git remote -v 没有输出，能否判断没有 GitHub 写入权限？**

不能。这个命令读取本地远程配置，并没有向 GitHub 验证账号权限。权限需要通过对应连接和操作另外验证。

**三：状态检查没有输出，是否代表程序通过测试？**

不是。状态检查关注文件变化，程序正确性需要实际运行和适当测试。

**四：为什么这次读取验收可以通过，但运行环境还没准备好？**

二者目标不同。读取验收证明任务拿到了教学文件并识别了代码起点；运行验收需要软件、配置、启动和功能证据。
